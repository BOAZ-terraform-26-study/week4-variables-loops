## 오늘의 지도: 값이 나가고, 블록 하나가 여러 개를 만듭니다

week1의 지도는 명령의 흐름, week2는 리소스 사이의 참조, week3은 state 파일이 사는 곳이었습니다. 오늘의 지도는 값이 어디에 적혀 있는지와, 블록 하나가 리소스 몇 개가 되는지입니다.

### ① BEFORE: 오늘 시작 시점 (week3 이 끝난 상태)

```
 ┌─ practice/network.tf ────────────────────┐        AWS 계정 (서울)
 │                                          │
 │  resource "aws_subnet" "public" {        │        subnet         1
 │    cidr_block        = "10.0.1.0/24"     │  ───>  association    1
 │    availability_zone = names[0]          │
 │  }                                       │        EC2            1
 │                                          │
 │  resource "aws_route_table_association"  │        VPC · IGW · RT
 │  resource "aws_instance" "web"           │        security group
 │                                          │
 └──────────────────────────────────────────┘

   블록 하나가 리소스 하나입니다.
   값은 리소스 블록 안에 그대로 적혀 있습니다.
   서브넷을 하나 더 만들려면 블록을 통째로 복사해야 합니다.
```

### ② AFTER: 오늘 끝날 때

```
 ┌─ variables.tf ─────────────┐  ┌─ network.tf ──────────────┐  ┌─ AWS ─────────┐
 │ subnets = {                │  │ resource "aws_subnet"     │  │ subnet      2 │
 │   a = { cidr, az }         │=>│   "public" {              │=>│ association 2 │
 │   c = { cidr, az }         │  │   for_each = var.subnets  │  │ VPC         1 │
 │ }                          │  │   each.key   -> Name      │  │ IGW         1 │
 │ primary_subnet_key = "a"   │  │   each.value -> cidr, az  │  │ route table 1 │
 │ my_ip      (sensitive)     │  │ }                         │  │ SG          1 │
 │ vpc_cidr                   │  │                           │  │ EC2         1 │
 ├─ locals.tf ────────────────┤  │ resource "aws_instance"   │  ├───────────────┤
 │ name_prefix                │=>│   subnet_id =             │=>│ 합계        9 │
 │ common_tags = merge(...)   │  │     public["a"].id        │  └───────────────┘
 └────────────────────────────┘  └───────────────────────────┘

   왼쪽 상자가 오늘 새로 생긴 것입니다. 가운데 상자의 블록 수는 week3 과 같습니다.
   오른쪽에서 늘어난 것은 subnet 과 association 둘뿐이고, EC2 는 그대로 1대입니다.
```

### ③ 인스턴스 key 지도: 주소가 번호일 때와 key 일 때

```
 count 로 만들면 : 주소가 번호입니다

   terraform_data.by_count[0]   "alpha"
   terraform_data.by_count[1]   "bravo"      <- 이 원소를 지웁니다
   terraform_data.by_count[2]   "charlie"

              list 에서 "bravo" 를 지운 뒤

   terraform_data.by_count[0]   "alpha"      그대로
   terraform_data.by_count[1]   "charlie"    -/+  교체
   terraform_data.by_count[2]   없음          -   삭제
                          ^
        "charlie" 는 값이 하나도 안 바뀌었는데 [2] 에서 [1] 로 옮겨졌습니다.
        state 는 리소스를 주소로 기억하므로 이 이동이 곧 교체입니다.


 for_each 로 만들면 : 주소가 key 입니다

   terraform_data.by_for_each["alpha"]
   terraform_data.by_for_each["bravo"]       <- 이 원소를 지웁니다
   terraform_data.by_for_each["charlie"]

              set 에서 "bravo" 를 지운 뒤

   terraform_data.by_for_each["alpha"]       그대로
   terraform_data.by_for_each["charlie"]     그대로
                              ^
        지운 것만 사라집니다. 나머지 주소는 움직이지 않습니다.
```

A-2 의 plan 마지막 줄이 이 그림 전체입니다. 숫자를 항목별로 나눈 표는 개념워크북 11번에 있습니다.

### [실습] [관찰 ✍️] A-2. count-demo: 인덱스가 밀리는 것을 먼저 봅니다 (5분)

지금 하는 일은 `count`와 `for_each`의 차이를 눈으로 만드는 것입니다. 이 폴더는 AWS를 건드리지 않습니다. `terraform_data`는 Terraform 내장 리소스라 provider 도 자격증명도 필요 없고 요금도 없습니다. `init` 출력에 provider 를 내려받는 줄이 없는 것도 그 때문입니다.

```bash
# pwd == practice/count-demo
cd practice/count-demo
terraform init
terraform apply     # yes
```

```
Apply complete! Resources: 6 added, 0 changed, 0 destroyed.
```

주소를 확인합니다.

```bash
# pwd == practice/count-demo
terraform state list
```

```
terraform_data.by_count[0]
terraform_data.by_count[1]
terraform_data.by_count[2]
terraform_data.by_for_each["alpha"]
terraform_data.by_for_each["bravo"]
terraform_data.by_for_each["charlie"]
```

위 셋은 번호이고 아래 셋은 key 입니다. 이제 `main.tf`를 열어 `names`의 기본값에서 가운데 `"bravo"`를 지웁니다.

```hcl
  default     = ["alpha", "charlie"]
```

apply 하지 말고 `plan`만 하세요.

```bash
# pwd == practice/count-demo
terraform plan
```

```
  # terraform_data.by_count[1] must be replaced
-/+ resource "terraform_data" "by_count" {
      ~ id               = "126a2864-24da-76a5-f1bb-d4f94985d892" -> (known after apply)
      ~ input            = "bravo" -> "charlie"
      ~ output           = "bravo" -> (known after apply)
      ~ triggers_replace = "bravo" -> "charlie"
    }

  # terraform_data.by_count[2] will be destroyed
  # (because index [2] is out of range for count)

  # terraform_data.by_for_each["bravo"] will be destroyed
  # (because key ["bravo"] is not in for_each map)

Plan: 1 to add, 0 to change, 3 to destroy.
```

Terraform 이 이유를 직접 적어줍니다. `(because index [2] is out of range for count)`와 `(because key ["bravo"] is not in for_each map)` 두 줄이 오늘의 결론입니다.

`by_count[1]` 옆에는 `must be replaced`만 있고 왜 교체되는지는 안 나오므로, `~ triggers_replace = "bravo" -> "charlie"` 줄을 보고 값이 밀려 들어온 것을 읽어야 합니다.

> [!TIP]
> `1 to add`가 왜 있는지 헷갈립니다. 교체 한 건은 삭제 하나와 생성 하나로 세어지기 때문입니다. 개념워크북 11번에 분해표가 있습니다.

지운 줄을 되돌려 놓으세요. C-2에서 destroy 할 때 6개가 맞아야 합니다.

```hcl
  default     = ["alpha", "bravo", "charlie"]
```

이제 `backend.tf`를 열어 `CHANGE-ME` 두 곳을 **week3 값**으로 바꿉니다. 방금 정한 `project_name`과 다른 값입니다. 버킷은 week3에서 만든 것을 그대로 씁니다.

```hcl
terraform {
  backend "s3" {
    bucket         = "boaz26-w3-kdh1834-tfstate"
    key            = "week04/app/terraform.tfstate"
    region         = "ap-northeast-2"
    dynamodb_table = "boaz26-w3-kdh1834-tflock"
    encrypt        = true
  }
}
```

> [!WARNING]
> `key`는 이미 채워져 있습니다. 건드리지 마세요. week3 리포에서 `terraform output -raw backend_config`를 복사해 오면 `key`가 `week03/app/terraform.tfstate`로 나옵니다. 그 줄까지 붙여넣으면 지난주 state 를 인수합니다.

```bash

```

```
Terraform has been successfully initialized!
```

### [실습] A-4. TODO ②③: `subnets` 와 `sensitive` (4분)

지금 하는 일은 서브넷 정의를 코드 밖으로 빼고, 공인 IP 를 화면에서 가리는 것입니다.

`variables.tf`의 TODO ② 주석을 풀어 채우세요. 값이 두 개(cidr, az)라서 `map(string)`으로는 담을 수 없습니다.

```hcl
variable "subnets" {
  description = "만들 퍼블릭 서브넷 목록. key 가 for_each 의 주소가 되므로 짧고 안 바뀌는 이름을 씁니다"

  type = map(object({
    cidr = string
    az   = string
  }))

  default = {
    a = { cidr = "10.0.1.0/24", az = "ap-northeast-2a" }
    c = { cidr = "10.0.2.0/24", az = "ap-northeast-2c" }
```

계정번호 12자리와 IP 를 가립니다. macOS 와 GNU 에서 `sed -i` 문법이 다르므로 파일을 새로 만드는 쪽이 안전합니다.

```bash
# pwd == practice
sed -E \
  -e 's/[0-9]{12}/<account-id>/g' \
  -e 's/([0-9]{1,3}\.){3}[0-9]{1,3}/x.x.x.x/g' \
  "../submissions/$ID/state-list.txt" > "../submissions/$ID/masked.txt"
mv "../submissions/$ID/masked.txt" "../submissions/$ID/state-list.txt"
```

커밋 직전에 확인합니다. 아무것도 안 나와야 정상입니다.

```bash
# pwd == week4-variables-loops
cd ..
git diff --cached | grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}|[0-9]{12}|AKIA[0-9A-Z]{16}'
git status --porcelain | grep -E 'terraform\.tfvars|\.tfstate|\.pem'
```

> [!CAUTION]
> 스크린샷도 마스킹하세요. 명령으로 걸러지지 않습니다. 가려야 하는 것은 공인 IP와 계정번호 12자리입니다.

## 부록. 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `Invalid for_each argument` | list 를 그대로 넣음 | map 을 쓰거나 `toset(list)`로 감싸기 |
| `The "for_each" value depends on resource attributes...` | key 에 아직 모르는 값을 씀 | key 는 변수와 상수로만 만들기. 값 쪽에는 리소스 속성을 써도 됩니다 |
| `Invalid index` | `primary_subnet_key`가 `subnets`에 없음 | TODO ④의 `validation` 확인 |
| `Error: Invalid value for variable` | `validation` 위반 | `error_message`가 요구하는 형식으로 값 수정 |
| `Error: Resource precondition failed` | `subnets`의 `az`가 이 계정에 없음 | `aws ec2 describe-availability-zones --region ap-northeast-2` |
| `Output refers to sensitive values` | `sensitive` 변수를 참조하는 output 에 표시 없음 | 그 output 에도 `sensitive = true` |
| `zsh: no matches found` | 주소의 대괄호를 셸이 해석 | 작은따옴표로 감싸기 |
| `Failed to get existing workspaces: S3 bucket ... does not exist` | week3 버킷 이름 오타 또는 bootstrap 없음 | A-1로 돌아가기 |
| `AccessDenied` on `init` | IAM 권한 부족 | week3 개념워크북 Part 3의 권한 목록 |
| `plan`이 9가 아닌 이상한 숫자 | `backend.tf`의 `key`가 week3 것 | apply 하지 말고 `key`를 `week04/app/...`으로 |
| `Error acquiring the state lock` | 동시 실행 또는 비정상 종료 | 아무도 작업 안 하는 것 확인 후 `terraform force-unlock <LOCK_ID>` |
| `Warning: Deprecated Parameter` | `dynamodb_table` 사용 | 정상입니다. week3 개념워크북 9번 |
| `destroy`가 SG/서브넷에서 멈춤 | ENI 잔존 | 잠시 후 재실행 |
